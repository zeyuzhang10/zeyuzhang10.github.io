最近调研了一些大模型多智能体系统，越来越觉得，目前很多所谓“多智能体协同”的工作，其实还没有真正证明协同本身带来了新的智能。

比较早期的工作是 Multi-Agent Debate：多个模型面对同一个问题，各自生成答案，再交换意见、讨论、投票。这类系统表面上像是多个智能体在合作，但本质上很多时候只是对同一个问题做多次采样，扩大了推理搜索的宽度。后续已经有工作指出，多智能体 Debate 的不少增益其实可以由独立采样、更多推理计算和最终投票解释，在控制总推理预算后，多智能体也未必比单智能体更强。因此，这类系统更像是分布式采样，而不是真正意义上的协同。

另一类常见方法是 Planner、Researcher、Coder、Reviewer 这种流程式多智能体系统，但如果这些所谓 Agent 背后使用的是同一个 LLM，看到的环境基本相同，能调用的工具也相同，那么它们更像是把一个复杂任务拆成多个上下文窗口，由外部程序负责流程控制和上下文管理。这种方法有很强的工程价值，但它的优势更多来自 context management 和 workflow orchestration，而不是多个独立智能体通过协同产生了单体原本没有的能力。

并且现有 benchmark 本身也限制了我们对“协同智能”的理解。数学题、知识问答、代码生成等任务本质上都是单个模型能够完成的任务，多 Agent 只是让同一个问题被多搞几遍。这样的 benchmark 不能说明为什么一定需要多个智能体，也很难证明多智能体有不可替代的价值。

**我现在更倾向于认为，一个真正的多智能体协同任务，应该天然存在多个智能体之间无法消除的边界：每个智能体拥有不同的局部状态、不同的行动能力，并且完成任务必须依赖其他智能体。与此同时，智能体间的信息交换还会让原本独立的决策过程产生，这也是为什么通信既可能传播有用信息，也可能传播错误，甚至形成错误共识**。

*换句话说，协同本身并不等于智能增益，它只是把多个原本独立的决策过程连接起来，真正的问题是这种连接到底带来了多少新的有效信息，又引入了多少错误相关性*。

也正因为如此，现在觉得具身可能比纯软 Agent 更自然地存在真正的多智能体协同。在这种场景下，没有任何机器人能够简单拥有其他机器人的全部感知和行动，因此协同本身开始具有不可替代性。相比现在很多“多个 LLM 一起做一道题”的工作，我更期待多智能体研究能够回答一个更基础的问题：**==如何把多个有限的智能体真正组织成单体无法替代的智能==**。只有当这个问题被回答清楚以后，我觉得我们讨论的才真是多智能体协同。
